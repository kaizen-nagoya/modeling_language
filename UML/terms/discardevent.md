# Q! UMLで廃棄イベントってどういうときに使いますか。
A1 by ChatGPT

UMLでいう**「廃棄イベント（discard event）」**は、主に**状態機械図（State Machine Diagram）**で、「あるイベントを受け取ったが、そのイベントを処理せず捨てる」ことを表すときに使います。

ポイントは、**「オブジェクトを廃棄する」ことではありません。**

### 1. 具体例

例えば、自動車のドア制御を考えます。

```text
             doorOpen
               ↓
        +---------------+
        |     OPEN      |
        +---------------+
```

ドアがすでに `OPEN` 状態なのに、もう一度 `open` イベントが来たとします。

```text
OPEN
 │
 │ open
 ↓
？？？
```

この `open` は意味がないので、

```text
OPEN
 │
 │ open / discard
 ↓
OPEN
```

のように、**イベントを廃棄する**という扱いができます。

---

### 2. なぜ「廃棄」が必要なのか

組込みシステムでは、イベントが必ずしも「処理すべきイベント」とは限りません。

例えば、

```text
状態        受信イベント
-------------------------
OFF         START → 処理
OFF         STOP  → 廃棄
RUNNING     START → 廃棄
RUNNING     STOP  → 処理
```

ということがあります。

特に、

- CANメッセージ
- センサイベント
- 割込み
- ボタン入力
- 通信パケット
- タイマイベント

などでは、**現在の状態では意味を持たないイベント**が発生することがあります。

---

### 3. UMLでは「無視（ignore）」との関係に注意

UMLでは、ここが少し紛らわしいところです。

状態に対してイベントが発生したとき、

**① 遷移を定義しない**

```text
RUNNING
   │
   │ START
   │
   ×
```

という場合もあります。

一方、

**② イベントを明示的に無視する**

という考え方もあります。

つまり、

> 「このイベントについては、この状態では何もしない」

ということをモデル上で明示したい場合です。

---

### 4. 「廃棄イベント」と「オブジェクトの削除」は別

ここは非常に重要です。

**廃棄イベント**

```text
event
 ↓
discard
```

は、

> **イベントを捨てる**

という意味。

一方、

**Destruction / Delete**

```text
object
 ↓
削除
```

は、

> **オブジェクトそのものを消滅させる**

という意味です。

UMLで後者を表す代表例が、ライフラインの最後を `X` で表す表現です。

---

### 5. 小川さんの論理回路設計なら、かなり使えます

例えば、以前のBMSを題材にすると、

```text
NORMAL
   │
   ├── OverVoltage → PROTECTION
   ├── OverCurrent → PROTECTION
   └── Start       → discard
```

とできます。

あるいは車載ECUなら、

```text
WAIT
 │
 ├─ valid CAN message → PROCESS
 ├─ invalid message   → discard
 └─ timeout           → FAULT
```

となります。

ここでは**discardとFAULTを区別することが重要**です。

```text
不要なイベント
      ↓
   discard
      ↓
   何もしない


異常イベント
      ↓
    FAULT
      ↓
   安全処理
```

この区別は、安全系・通信系の設計ではかなり重要です。

---

### 6. RTLにするとどうなるか

例えば、

```text
IDLE
  ├── START → RUN
  └── STOP  → discard

RUN
  ├── STOP  → IDLE
  └── START → discard
```

なら、Verilogでは概念的に、

```text
case (state)
  IDLE:
    if (start)
      state <= RUN;
    // stop は何もしない

  RUN:
    if (stop)
      state <= IDLE;
    // start は何もしない
endcase
```

となります。

つまり、**UMLの「廃棄」は、RTLでは「そのイベントによって状態を変更しない」という設計に対応させられる**わけです。

このため、ロバストネス図から状態機械、さらにVerilogへつなげる教材では、**「処理するイベント」「無視するイベント」「異常として処理するイベント」**の3つを区別させる演習がかなり有効です。
